# 018 — Провайдеры озвучки: Kokoro и Lumean (ElevenLabs / Cartesia)

## Что сделано

Озвучку можно выбрать в Settings: локальный Kokoro (CPU/GPU, см. 017) или облачный Lumean.
Для Lumean выбирается сервис (ElevenLabs или Cartesia) и вводится API-ключ.

### Бэкенд
- `app-settings/app-settings.schema.ts`: `ttsProvider` (`kokoro` | `lumean`), `kokoroDevice`,
  `lumeanService` (`elevenlabs` | `cartesia`), `lumeanApiKey`. Патч принимает `lumeanApiKey: null` для удаления ключа.
- `app-settings/app-settings.service.ts`: полные настройки (с ключом) — только серверная `get()`.
  Наружу отдаётся `getPublic()`: ключ заменён флагом `lumeanApiKeySet` и подсказкой `…ABCD`.
  Файл `<projects>/_app-settings.json`.
- `tts/lumean-tts.adapter.ts` (новый): цикл Lumean для одного чанка:
  1. `POST /templates` с голосом и скоростью (шаблон кешируется в памяти по сервису, голосу и скорости);
  2. `POST /orders` (`type: "tts"`, `template_id`, `input_text`);
  3. опрос `GET /orders/{id}` раз в 3 с до `completed` / `result_delivered`;
  4. `POST /storage/url` по пути из `result.files[0]`, затем скачивание WAV по временной ссылке.
  Скорость ограничивается диапазоном сервиса (ElevenLabs 0.7–1.2, Cartesia 0.6–1.5).
  Заголовок `X-API-KEY`. Таймаут `LUMEAN_TIMEOUT_MS` (по умолчанию 10 минут) на весь чанк.
  Ошибки `failed`, `compensated`, `cancelled`, `partially_completed` попадают в лог задачи с текстом Lumean.
- `tts/tts-synthesizer.service.ts` (новый): выбирает Kokoro или Lumean по настройке на каждый чанк.
  `TtsProcessor` теперь зависит от него, а не от `KokoroTtsAdapter`.
- `tts/utils/write-audio-response.util.ts` (новый): общая потоковая запись аудио в файл, её используют оба адаптера.
- `projects/settings.controller.ts`: `GET /api/settings/voices` возвращает голоса выбранного провайдера.
  Для Lumean берётся первая страница библиотеки (100 голосов). Без ключа — 400 с подсказкой.
- `projects/catalog.service.ts`: `getLumeanVoices(service, key)`. ElevenLabs — `/voices/elevenlabs/library`,
  Cartesia — `/voices/cartesia`.
- `docker-compose.yml`, `.env.example`, `backend/.env.example`: `LUMEAN_API_URL`, `LUMEAN_TIMEOUT_MS`.

### Фронтенд
- Settings: блок «Narration provider» (Kokoro / Lumean). Для Kokoro — переключатель CPU/GPU.
  Для Lumean — выбор сервиса, поле API-ключа (тип password), «Save key», «Remove key» и показ сохранённого ключа по подсказке.
- После смены провайдера инвалидируется список голосов (`['settings','voices']`).
  Уже сохранённый голос проекта не меняется: если его нет в новом списке, форма создания не отправится.

- `tts/tests/tts-overrides.spec.ts`: мок переведён на `TtsSynthesizerService`.

## Не проверено против реального API
- Не было ключа Lumean, поэтому реальные запросы не выполнялись. Форматы из документации (`api.lumean.app/docs/llm.md`)
  реализованы по описанию, тесты используют моки.
- Неизвестно точно: принимает ли ElevenLabs-шаблон `output_settings` внутри `config` (принято по описанию);
  формат ответа Cartesia-списка голосов (принято `data.items`, как вариант); допустимость `voice_id` из библиотеки
  для шаблона без подключения голоса в аккаунте.
- Нет поиска по голосам: список — первые 100 записей библиотеки.

## Ограничения
- Ключ хранится в `_app-settings.json` открытым текстом (принято).
- Шаблоны кешируются в памяти процесса: после перезапуска API создаётся новый шаблон (на стоимость почти не влияет).
- Lumean медленнее Kokoro: каждый чанк — отдельный заказ с опросом.
