# 016 — Автоматический монтаж: выбор стоковых клипов при создании эпизода

## Проблема

Раньше стоковые видео можно было загрузить только во вкладке «Stock video track»
**после** генерации сценария и озвучки. Затем пользователь вручную нажимал Build.
Пайплайн не был полностью автоматическим.

## Что сделано

Пользователь выбирает клипы (файлы или целую папку) прямо в форме **Create episode**,
той же дропзоной, что и во вкладке видео. После этого всё идёт без участия пользователя:

```
Create episode ─┬─> сценарий -> TTS -> мастеринг аудио ──┐
                └─> фоновая загрузка клипов в проект ────┴─> build (normalize -> plan -> render -> mux)
```

### Жизненный цикл `state.video.autoMontage.status`

| Статус      | Значение                                                                  | Кто переводит дальше |
|-------------|---------------------------------------------------------------------------|----------------------|
| `uploading` | Проект создан, браузер заливает клипы                                     | фронтенд, `POST .../auto-montage/uploaded` |
| `pending`   | Клипы загружены, ждём `status === 'COMPLETED'`, `!mixNeedsRebuild`, `outputFiles.wav` | `AutoMontageService` |
| `rendering` | Запущен обычный job `build`, его id лежит в `jobId`                       | `AutoMontageService` |
| `done`      | Job завершился, финальный MP4 готов (или ручной job уже дал `video.output`) | — |
| `failed`    | Нет валидных клипов, ошибка job, отмена, или job заменён без результата; текст в `error` | — |

- `backend/src/modules/video/auto-montage.service.ts` (**новый**), зарегистрирован в `video.module.ts`:
  - `markUploaded(projectId, uploaded)`: переводит `uploading` в `pending`, а если в библиотеке

  - `tick()` раз в 10 с (с защитой от наложения тиков) проходит по проектам в `pending`/`rendering`:
    - `pending` и аудио готово: `VideoJobService.start(id, 'build')` со стилем проекта.
      `ConflictException` (уже идёт другой видео-job) означает «повторить на следующем тике»;
    - `rendering`: следит за `video.job` и ставит `done` или `failed`.
  - Выбран опрос, а не вызов из `FfmpegService.masterProject`, потому что `VideoModule` уже импортирует
    `AudioModule` (прямой вызов дал бы цикл модулей). Опрос также переживает перезапуск API:
    состояние хранится в `state.json`.
- `backend/src/modules/video/video.controller.ts`: новый эндпоинт
  `POST /api/projects/:id/video/auto-montage/uploaded` с телом `{ uploaded: number }`.
- Тесты: `backend/src/modules/video/tests/auto-montage.spec.ts` (8 кейсов). В `video-api.spec.ts`

## Ограничения и известные моменты

- Клипы загружаются из браузера, поэтому **вкладку нужно держать открытой до конца загрузки**.
  При перезагрузке страницы недогруженные файлы теряются: догрузите их вручную в библиотеку
  и нажмите «Continue automatic montage».
- Клипы копируются в проект (`projects/<id>/video/library`), как и при ручной загрузке. Дубликаты отсекаются по sha256.
- Если после мастеринга стоит `mixNeedsRebuild` (громкость музыки изменили, а микс не пересобрали),
  автомонтаж ждёт пересборки микса.
- Автомонтаж запускается один раз. Повторный мастеринг (например, смена громкости) видео не пересобирает,
  для этого нажмите Build вручную.
