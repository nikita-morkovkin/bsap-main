# 017 — Переключатель CPU/GPU для Kokoro

## Что сделано

Синтез речи по-прежнему идёт через `kokoro-fastapi`, но теперь есть два сервиса:
CPU (всегда запущен, `kokoro-tts`) и GPU (опциональный, `kokoro-tts-gpu`, профиль `gpu`).
Выбор хранится в настройках приложения и применяется к следующему чанку.

### Бэкенд
- `backend/src/modules/app-settings/` (новый модуль):
  - `app-settings.schema.ts`: `{ kokoroDevice: 'cpu' | 'gpu' }`, по умолчанию `cpu`.
  - `app-settings.service.ts`: читает и пишет `<projects>/_app-settings.json` атомарно через `writeArtifact`.
    Файл лежит в корне проектов, поэтому не попадает в список эпизодов (там фильтр по формату ID).
  - `app-settings.controller.ts`: `GET /api/app-settings`, `PUT /api/app-settings` (частичное обновление, валидация zod).
- `StateManagerService.getProjectsDirectory()` стал публичным, чтобы модуль настроек нашёл папку.
- `kokoro-tts.adapter.ts`: берёт `KOKORO_TTS_URL` (CPU) или `KOKORO_GPU_TTS_URL` (GPU) в зависимости от настройки.
  Кеш голосов теперь отдельный для каждого URL. Если сервис недоступен, ошибка объясняет, как его запустить
  (`docker compose --profile gpu up -d kokoro-tts-gpu`) или переключиться на CPU.
- `tts.module.ts` и `app.module.ts` подключают `AppSettingsModule`.

### Docker / конфигурация
- `docker-compose.yml`: сервис `kokoro-tts-gpu` (образ `kokoro-fastapi-gpu`, `profiles: ["gpu"]`, GPU через `deploy.resources`).
  Без `--profile gpu` он не стартует, и на машинах без NVIDIA всё работает как раньше.
- Переменная `KOKORO_GPU_TTS_URL` (по умолчанию `http://kokoro-tts-gpu:8880`) в `docker-compose.yml`, `.env.example`, `backend/.env.example`.

### Фронтенд
- Новая вкладка «Settings» (`NavigationTab` и `Navigation`), экран `views/settings/SettingsView.tsx`.
- Переключатель CPU / GPU (NVIDIA) с подсказкой, как запустить GPU-сервис.
- `api/app-settings.api.ts`, `hooks/queries/useAppSettings.hook.ts`, тип `AppSettings` в `settings.types.ts`.

## Тесты
- `tts/tests/kokoro-voice.spec.ts`: два новых кейса (GPU-URL используется; понятная ошибка при недоступном GPU).
- `app-settings/app-settings.spec.ts`: значение по умолчанию, сохранение и отказ на неверном значении.
- Старые тесты адаптера обновлены: передают заглушку настроек.
- `tsc` и eslint по затронутым модулям без новых ошибок. Прежняя ошибка в `exports-api.spec.ts` не менялась.

## Не покрыто
- Фронтенд не проверен локально (нет `node_modules`), проверка типов идёт при сборке Docker.
- GPU-сервис не запускался: на текущей машине (Mac) Docker не даёт доступа к NVIDIA GPU.
- Смена устройства не перезапускает уже отрисованные чанки.
